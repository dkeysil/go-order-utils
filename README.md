# go-order-utils

Golang utilities used to generate and sign orders from Polymarket's CTF Exchange.

This library targets **CTF Exchange V2** (EIP-712 domain version `"2"`, live 2026-04-22).
For the V1 order format use commit `9383993` or earlier.

### V2 highlights

- Order struct: signed fields are `salt, maker, signer, tokenId, makerAmount, takerAmount, side, signatureType, timestamp, metadata, builder` (`ORDER_TYPEHASH = 0xbb86318a2138f5fa8ae32fbe8e659f8fcf13cc6ae4014a707893055433818589`).
- `timestamp` is unix milliseconds and replaces V1's `nonce`.
- `feeRateBps` is gone — fees are set at match time by the operator.
- New optional fields: `metadata` (bytes32) and `builder` (bytes32 builder code) for attribution.
- New signature type: `POLY_1271` (EIP-1271 smart-contract wallets). For this
  type `BuildSignedOrder` skips the local ecrecover check — the signature is
  validated on-chain via `isValidSignature`, and callers must ensure the
  contract authorizes the EOA whose key they pass.
- V2 exchange addresses are the same on mainnet (137) and Amoy (80002):
  - `CTFExchange V2`: `0xE111180000d2663C0091e4f400237545B87B996B`
  - `NegRisk CTFExchange V2`: `0xe2222d279d744050d28e00520010520000310F59`

Signed-order golden vectors in the test suite are generated by
`py-clob-client-v2==1.0.0` via `scripts/gen_v2_vectors.py`.

### Removed in V2

The V1-generated `pkg/contracts/{exchange,exchange-fees,neg-risk,neg-risk-fees}`
bindings were removed. Their ABI no longer matches the V2 deployments at the
addresses exposed by `config.GetContracts`. Consumers that need contract
bindings should regenerate them with `abigen` from the V2 contract ABIs.
