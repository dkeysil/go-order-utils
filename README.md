# go-order-utils

Golang utilities used to generate and sign orders from Polymarket's CTF Exchange.

This library targets **CTF Exchange V2** (EIP-712 domain version `"2"`, live 2026-04-28).
For the V1 order format use commit `9383993` or earlier.

### V2 highlights

- Order struct: signed fields are `salt, maker, signer, tokenId, makerAmount, takerAmount, side, signatureType, timestamp, metadata, builder` (`ORDER_TYPEHASH = 0xbb86318a2138f5fa8ae32fbe8e659f8fcf13cc6ae4014a707893055433818589`).
- `timestamp` is unix milliseconds and replaces V1's `nonce`.
- `feeRateBps` is gone — fees are set at match time by the operator.
- New optional fields: `metadata` (bytes32) and `builder` (bytes32 builder code) for attribution.
- New signature type: `POLY_1271` (EIP-1271 smart-contract wallets). For
  Polymarket deposit wallets the wire signature is an **ERC-7739 composite**
  — `innerSig(65) || appDomainSep(32) || contentsHash(32) || orderTypeString
  || uint16_BE(len)` — produced by `BuildSignedOrder` when `OrderData.SignatureType
  = POLY_1271`. Both `Maker` and `Signer` must be set to the deposit wallet
  contract address; the EOA whose key is passed is what the wallet's
  `isValidSignature` validates internally. This format is **not** the same as
  the bare 65-byte signature earlier versions of this fork emitted for
  `POLY_1271`.
- V2 exchange addresses are the same on mainnet (137) and Amoy (80002):
  - `CTFExchange V2`: `0xE111180000d2663C0091e4f400237545B87B996B`
  - `NegRisk CTFExchange V2`: `0xe2222d279d744050d28e00520010520000310F59`

EOA / proxy / Safe golden vectors are generated by `py-clob-client-v2==1.0.0`
via `scripts/gen_v2_vectors.py`. POLY_1271 (ERC-7739) goldens come from
`@polymarket/clob-client-v2` at commit `f7307a8` (deposit wallet init).

### Deposit wallet onboarding (`pkg/depositwallet`)

Deposit wallets execute approved actions via signed `Batch` messages: the
wallet owner signs an EIP-712 `Batch{wallet, nonce, deadline, Call[] calls}`
under the `DepositWallet/1` domain (`verifyingContract` = the wallet itself),
and the relayer submits it as a `WALLET`-typed transaction. `pkg/depositwallet`
exports `SignBatch` and the underlying `HashBatch` / `BatchDigest` helpers.
HTTP transport to the relayer is the caller's responsibility.

### Contract bindings

`pkg/contracts/exchange` holds `abigen`-generated bindings for the V2
CTF Exchange. The same ABI is deployed at both V2 addresses (standard and
neg-risk), so a single binding package handles both — instantiate with the
address returned by `config.GetContracts(...).Exchange` or `.NegRiskExchange`.

The V1-era `exchange-fees` and `neg-risk-fees` fee-module bindings are not
regenerated: V2 fees are set by the operator at match time rather than via a
separate on-chain fee module contract.

The bindings were generated from the ABI in
`@polymarket/clob-client-v2` (`src/order-utils/abi/ExchangeV2.ts`); see
`scripts/gen_v2_vectors.py` header and the commit log for details.
